02 / HOW IT FITS

One folder.
One clear job.

Every skill is a small package you can read before running. The agent makes a plan; deterministic scripts handle the repeatable bits.

Read the field guide ↗
01

Inspect the package

Read SKILL.md and manifest.json first. Know the requirements before you run anything.

⌕
02

Check the prerequisites

Confirm the named binaries and files exist. If something is missing, stop and report it—no hidden installs.

✓
03

Run, then verify

Use the included script where applicable. Confirm its output instead of inventing a success story.

↗

03 / NON-NEGOTIABLES

Trust is a feature.

Why these rules? ↗
01

No HTML in skill repos

Skills produce plans and decisions—not markup that pretends to be an installable tool.

02

No live credentials

Keys, OAuth state, and checkout IDs never belong in tracked files or URLs.

03

Canonical links only

Reference the real platform handle; don’t ship session-bound or live-checkout links.

04

Referral means disclosed

If a link can earn a credit, the plain-language disclosure stays right beside it.

05

No fake gates

A client-side checkbox is not verification. Don’t claim a gate that doesn’t exist.

06

Hashes are checked

make verify checks manifest-recorded file hashes for consistency.

04 / GET STARTED

Clone it.
Read it. Use it.

No package manager. No site build. Clone the umbrella repo, verify the packages, then copy the skill you want into your custom-skills folder.

Full installation notes ↗
YOUR TERMINAL / 3 COMMANDS
$ git clone https://github.com/Git-FED/fed-os-muse-skills.git
$ cd fed-os-muse-skills && make verify
$ cp -r skills/muse-footer-layout ~/workspace/custom-skills/

Inspect SKILL.md before handing a skill to an agent.
