01

MEDIA / FFMPEG + FFPROBE

muse-video-editor

Turn a source clip into a checked vertical cut with burned-in captions. It probes before processing, uses a deterministic ffmpeg script, and verifies the output instead of guessing.

Workflow

  1. Confirm the source exists and probe its dimensions.
  2. Check both ffmpeg and ffprobe are available.
  3. Run the cut script, then inspect the output file and size.

Requires / produces

ffmpeg, ffprobe, readable input and writable output folders.

Output H.264/AAC vertical video at 1080 × 1920.

02

LINKS / INFORMATION DESIGN

muse-footer-layout

Classify links by visibility and draft a public footer plan plus a separate gated list. Unknown links stop the process—no optimistic guessing.

Workflow

  1. Check reference data and required tools.
  2. Classify each URL as Public, Premium, Private, Internal, or Unknown.
  3. Keep private/internal entries out; disclose referral links.

Requires / produces

bash, jq, and the bundled link references.

Output Plain-text footer plan and gated list; no HTML.

03

RELEASE / DOMAIN SAFETY

muse-cname-guard

Scan a repository for a stray CNAME file that could point GitHub Pages at an unintended domain. A finding is surfaced for the owner to decide; it is never deleted silently.

Workflow

  1. Confirm bash and find are present.
  2. Run the repository check from the project root.
  3. Stop release on a finding and show the exact path.

Requires / produces

bash and find on the path.

Output One clear OK or FORBIDDEN verdict.

04

CLOUDFLARE / DEPLOY PREFLIGHT

muse-cloudflare-deploy

Inspect a dry-run deployment before anything goes live. Catch a wrong target, oversized bundle, leaked binary, or exposed secret before the deploy decision.

Workflow

  1. Confirm Wrangler, Node, and project config.
  2. Verify local state is ignored and inspect dry-run assets.
  3. Run the secrets check; deploy only after both checks pass.

Requires / produces

wrangler, node, Wrangler config, and credentials available to Wrangler via environment.

Output Dry-run size report, leak checks, and pass/fail.

05

FUNDING / TRANSPARENCY

muse-funding-buttons

Plan funding surfaces in a consistent order, referencing providers by canonical handle. Live checkout URLs, embed IDs, and credentials stay out of the plan.

Workflow

  1. Load the bundled funding reference data.
  2. Resolve each provider handle and classify the surface.
  3. Emit label, handle, class, gate, and disclosure—never secrets or live URLs.

Requires / produces

bash, jq, and bundled funding references.

Output Ordered funding plan, with referral disclosure where needed.
